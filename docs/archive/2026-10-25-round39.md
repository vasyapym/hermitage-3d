## Hunt / found / fixed
SALVAGE ×2:

The kit-layout canvas-prefix bug: indexOfName sliced 'frame_'.length (6) for BOTH roles; canvas_ is 7 characters, so every canvas part parsed to null and the merge would throw at mount. The fence caught it BEFORE the browser run.
The hop query: the deep-link legs must carry the FULL det query (a sliced query drops at= and flips the time mode mid-walk).

THE THIRD SALVAGE, the round's real find: the R1 glb NEVER PARSED in any browser.

Symptom: the smoke's 1812 legs died with RangeError: Invalid typed array length: 465 inside three's EXT_meshopt_compression decoder.
Audit: a node parse of every committed glb showed the LAST 19 meshopt-compressed bufferViews declaring bytes beyond the written BIN (435,632+465 > 436,044…).
Cause: repackBin (tools/common.mjs) pushed each meshopt view's OUTER byteOffset/byteLength (the DECODED data's coordinates in the dropped fallback buffer) as a real data range. subarray clamped those to empty, the cursor still advanced, every later mapped offset shifted, and the tail chunks fell off the written BIN. Jordan/rastrelli survived by luck (their outer offsets stayed inside the source BIN); the canary _check carried the same 6-view defect.
Repair, per AGENTS.md rule 4 (assets as code): the repack law now copies a meshopt view's compressed range ONLY (the outer coordinate rides verbatim, three ignores it) and fails LOUD on any range beyond the source BIN. Both rooms were regenerated through the committed chain (gltf + manifest steps); the parquet re-encode reproduced its committed sha byte-for-byte (the R2 determinism proof holding). The kit/accessor data is untouched: a container repair, not an art change.

THE FOURTH SALVAGE, from the probe's own census (draws 0 / tris 0 at the SETTLED room; the HUD's ledger 27,413,409 B, the room mounted and drew NOTHING):

Cause: the merged geometries held RAW KHR_mesh_quantization Int16 codes. three's BufferAttribute.applyMatrix4 reads DENORMALIZED (getComponent) but WRITES through the attribute's own normalized Int16 setter, so clone().applyMatrix4(matrixWorld) re-encoded + clamped the result and the merged tree collapsed to a ~1.6 m bubble at the origin; every camera's frustum culled it. Jordan/gallery never merge (the GL normalizes their accessors natively at render), which is why the law stayed invisible until the first CPU-side merge.
Fix in room.ts: dequantizeGeometry materializes EVERY attribute into Float32 via getComponent (the denormalization applied) BEFORE applyMatrix4 bakes the world transform; renormalizeNormals keeps the merged normals unit (applyNormalMatrix composes the node's 27.5× scale; the lighting law needs unit normals exactly as the GL's native read delivers them).
