## Verdicts
### DEC-039 — The environment handover (R24-ux): the departing interior's unmount clears the ONE environment slot only when it still owns it — per-load handles, disposal always of the room's own saved resource

Census (MEASURED the same day):

Fresh #/1812 luminance is 31/100 with the environment bound.
jordan→1812 reads ≈15 with the slot NULL.
gallery→jordan reads ≈65 vs fresh ≈81.
EVERY interior→interior handover is affected. Only the square path is immune, because residents are never disposed (DEC-013).


Mechanism (code-verified):

The unmounts called scene.setEnvironment(null) unconditionally.
dispose-from fires ONE TRANSIT AFTER the hold, and the destination's mount publishes ITS PMREM probe INSIDE the hold (ADR-0013).
So the departing room cleared the NEWCOMER'S handle and nothing re-bound it.
The gilt kit (metallic, sun/hemisphere hidden indoors) collapsed to near-black. Exposure measured 1.0 on every row, so it was never the variable.


Fix law:

The scene keeps ONE slot.
The room module saves the handle its OWN mount created (envHandle, per-load).
The unmount releases through src/assets/environment-slot.ts: releaseOwnedEnvironment(facade, owned, disposeResource).

It clears ONLY on exact identity; contents-equal objects are NOT ownership.
It then disposes the own resource REGARDLESS, never early-returning.
The loaders' disposeEnvironment(roomId) already disposes exactly the owner's entry (verified unchanged).


The RoomScene facade gains clearEnvironmentIfCurrent(handle), implemented over the real scene.
The three interior modules (rastrelli-gallery, jordan, 1812) adopt the identical release shape. The 1812 unbaked canary branch rides the null-owned case.
NO change to the FSM/applySwap/disposeFrom/scheduling. The overlap visibility policy (departing meshes lit by the newcomer's probe during the exit frames) stays as-is.


Rejected alternatives (the reply's):

never-clear: breaks the square return.
presence-checks: presence is not ownership.
dispose-whatever-the-scene-references: destroys the newcomer.
rebind-after-dispose: a needless second publication.
reorder-disposal-before-mount: violates the stated overlap/exit-only law.
